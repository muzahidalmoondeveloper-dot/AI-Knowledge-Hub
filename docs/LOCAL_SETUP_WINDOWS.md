# Local setup on Windows

Use PowerShell unless a step explicitly names the Visual Studio command prompt. No Docker, Poetry, Pipenv or uv is used.

## 1. Prerequisites

Install 64-bit Python 3.12/3.13 from python.org, Node.js 22, and Git. Confirm `python --version`, `node --version`, `npm.cmd --version`, and `git --version`. `npm.cmd` works even when PowerShell blocks `npm.ps1`.

Install PostgreSQL 18 using the installer linked by the [PostgreSQL Windows download page](https://www.postgresql.org/download/windows/). Include the server, command-line tools and headers/development files. Record the `postgres` password and port. The installer normally creates a Windows service. Inspect with:

```powershell
Get-Service '*postgres*'
$env:Path = 'C:\Program Files\PostgreSQL\18\bin;' + $env:Path
psql --version
```

## 2. Install pgvector

The Python `pgvector` package is only the client. PostgreSQL also needs the native extension DLL, control and SQL files. Follow the [upstream Windows instructions](https://github.com/pgvector/pgvector#windows).

Install Visual Studio Build Tools with C++ desktop support. Open **x64 Native Tools Command Prompt for VS** as administrator. These commands are for that **cmd** prompt, not PowerShell:

```bat
set "PGROOT=C:\Program Files\PostgreSQL\18"
cd %TEMP%
git clone --branch v0.8.7 https://github.com/pgvector/pgvector.git
cd pgvector
nmake /F Makefile.win
nmake /F Makefile.win install
```

Use the PostgreSQL version you actually installed in `PGROOT`; a 64-bit build must match the server architecture. Missing `postgres.h` means the development files or `PGROOT` are wrong. Access denied at installation means this command prompt needs administrator privileges. Do not download an arbitrary DLL from an untrusted source.

## 3. Create a database

Back in PowerShell:

```powershell
& 'C:\Program Files\PostgreSQL\18\bin\psql.exe' -h localhost -U postgres -d postgres -W
```

In psql, run:

```sql
CREATE ROLE akh LOGIN;
\password akh
CREATE DATABASE ai_knowledge_hub OWNER akh;
\connect ai_knowledge_hub
CREATE EXTENSION IF NOT EXISTS vector;
SELECT extversion FROM pg_extension WHERE extname = 'vector';
\quit
```

Use a dedicated `akh` role for the application rather than a superuser. The extension is enabled by the administrator once. Alembic also issues `CREATE EXTENSION IF NOT EXISTS vector`; it will be a no-op after this step. URL-encode reserved characters in the database password when placing it in the connection URL.

## 4. Python environment and configuration

From `D:\AI Knowledge Hub`:

```powershell
python -m venv backend/env
.\backend\env\Scripts\python.exe -m pip install --upgrade pip
.\backend\env\Scripts\python.exe -m pip install -r backend/requirements.lock.txt
.\backend\env\Scripts\python.exe scripts/init_env.py
notepad backend/.env
```

Set `DATABASE_URL=postgresql+asyncpg://akh:YOUR_URL_ENCODED_PASSWORD@localhost:5432/ai_knowledge_hub` and your own `BOOTSTRAP_ADMIN_EMAIL`. Keep the generated keys. If `.env` already exists, the script refuses to overwrite it. No venv activation is required when using its Python executable directly. If desired, enable script execution only for the current terminal with `Set-ExecutionPolicy -Scope Process Bypass`, then `.\backend\env\Scripts\Activate.ps1`.

Required/optional settings:

| Variable | Purpose |
|---|---|
| DATABASE_URL | asyncpg SQLAlchemy URL; PostgreSQL only |
| JWT_SECRET_KEY | random signing secret, at least 32 characters |
| ENCRYPTION_KEY | valid Fernet key, generated by helper |
| BOOTSTRAP_ADMIN_EMAIL | exact trusted initial administrator email |
| CORS_ORIGINS | JSON list, default localhost:5173 |
| PROVIDER_ORIGINS | JSON list of exact trusted scheme/host/port origins |
| UPLOAD_DIRECTORY | private local file directory, default `uploads` |
| MAX_UPLOAD_SIZE_MB | application upload size limit, default 20 |
| HISTORY_MESSAGES / HISTORY_CHARACTERS | bounded LLM context, default 12 / 24000 |
| WORKER_LEASE_SECONDS | generation processing deadline, default 900 |
| COOKIE_SECURE | false for local HTTP; true behind HTTPS |
| ACCESS_MINUTES / REFRESH_DAYS | session expiration, defaults 15 / 14 |

Base URL paths such as `/v1` are configured on providers in the dashboard. The allowlist contains origins without paths. Only administrators can choose endpoints and credentials. Custom DNS names must be administrator-controlled; do not allow user-controlled names or mutable public DNS resolving to internal services. Local providers must use loopback origins. Ollama `:cloud` models cannot be declared local.

## 5. Migrate the database

Always run from `backend` so relative `.env`, migration and upload paths agree:

```powershell
cd backend
.\env\Scripts\python.exe -m alembic upgrade head
.\env\Scripts\python.exe -m app.db.setup_checkpoints
.\env\Scripts\python.exe -m alembic current
```

The first command installs the 14 application tables and indexes. The second installs LangGraph's maintained checkpoint tables using psycopg. Application queries use SQLAlchemy + asyncpg; the checkpoint integration uses its own supported psycopg connection. The application does not call `create_all()` at startup.

## 6. Install Ollama and models

Install the Windows application from the [official Ollama download page](https://ollama.com/download/windows). Open a new terminal after installation:

```powershell
ollama pull llama3.2:3b
ollama pull nomic-embed-text
ollama list
Invoke-RestMethod http://localhost:11434/api/tags
```

Ollama normally starts in the system tray. Use `ollama serve` only if it is not already listening. Select models appropriate to your memory/GPU; the initial chat model is configurable. Use exactly the same tag in the dashboard that `ollama list` shows. Do not use a `:cloud` tag for private local processing.

## 7. Start three processes

Terminal 1, in `backend`:

```powershell
.\env\Scripts\python.exe -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000 --loop app.core.event_loop:selector_loop --no-access-log
```

Terminal 2, in `backend`:

```powershell
.\env\Scripts\python.exe -m app.workers.ingestion
```

Terminal 3, in `frontend`:

```powershell
npm.cmd ci
npm.cmd run dev
```

Visit `http://127.0.0.1:5173`, register your configured administrator email, and follow README's first workflow. Access tokens stay in memory; refresh cookies are HttpOnly/SameSite Strict. Reloading restores the session through refresh. API documentation is at `http://127.0.0.1:8000/docs`; `/health` checks database connectivity. Use the same browser host consistently. Both localhost and 127.0.0.1 are allowed by the example CORS settings. Do not expose the development server directly to the internet.

The `--loop app.core.event_loop:selector_loop` option is necessary for psycopg asynchronous checkpoints on Windows, including when Uvicorn runs without reload. The checkpoint setup script selects that loop directly. This uses Python 3.12+ loop factories rather than deprecated global loop policies.

If another application uses these ports, choose a free backend port with `--port`, copy `frontend/.env.example` to `frontend/.env`, set `VITE_API_PROXY_TARGET` and `VITE_PORT`, and add the matching frontend origin to backend CORS. Restart Vite after editing its environment. `strictPort` prevents silently serving on an unexpected port.

If a managed environment disallows writing user caches, use `pip install --cache-dir '..\.pip-cache' ...` or `npm.cmd ci --cache '..\.npm-cache'` from their respective project directories.

## 8. Tests and build

```powershell
cd backend
.\env\Scripts\python.exe -m pytest -q
.\env\Scripts\python.exe -m pip check
.\env\Scripts\python.exe -m ruff check app tests
.\env\Scripts\python.exe -m alembic upgrade head --sql
$env:RUN_OLLAMA_TESTS='1'
.\env\Scripts\python.exe -m pytest -m ollama -q
Remove-Item Env:RUN_OLLAMA_TESTS
```

For the vector integration test, create a **dedicated disposable test database**, enable pgvector, migrate it with `DATABASE_URL` temporarily set to its URL, and run checkpoint setup. Then set `TEST_DATABASE_URL` to that migrated database URL and run `python -m pytest -m integration -q`. Never point tests at production. Integration fixture inserts are rolled back; migrations are not. Restore `DATABASE_URL` afterwards.

```powershell
cd ../frontend
npm.cmd test
npm.cmd run build
```

For a cloud integration, register a real key in the provider dashboard, test the provider, and use a separate non-sensitive sample knowledge base with explicit cloud consent. Default tests never make paid calls.

## Troubleshooting

- `extension vector is not available`: install the native server extension for the PostgreSQL major version, then enable it in this database.
- `password authentication failed`: check database role/password and URL encoding. Do not change PostgreSQL authentication to trust.
- Queued documents never change: run the worker in the correct `backend` directory with the same `.env` as the API.
- Failed document: inspect its safe error text and job attempts; test the embedding model; retry using Reindex. No partial chunks are searchable.
- Empty scanned PDF: OCR it outside the application, then upload the searchable PDF.
- `dimension_mismatch`: register the actual output dimensions in a new embedding configuration and reindex the knowledge base.
- Local model timeout: test Ollama directly, choose a smaller model, or increase the bot timeout up to 300 seconds.
- Unexpected refusal: inspect evidence, adjust top-k/threshold, or improve source text. Strict mode rejects non-verbatim model output.
- Sign-in refresh fails: use `localhost:5173` consistently; changing browser host changes cookie scope/site. Set correct allowed origin for a new host.

Production static hosting needs an SPA fallback to `index.html` and a same-origin `/api` proxy to FastAPI with SSE buffering disabled and sufficiently long request timeouts. Set secure cookies and exact HTTPS origins; keep provider endpoints and PostgreSQL private.
